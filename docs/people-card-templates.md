# Плитки людей на /people: как выбирать компоновку

Документ для агента (или человека), который размечает плитки в
[`src/data/people.json`](../src/data/people.json). Вёрстка —
[`src/styles/widgets/people-cards.css`](../src/styles/widgets/people-cards.css),
разметка — [`src/includes/macros/people-card.njk`](../src/includes/macros/people-card.njk).

## Базовая компоновка

Плитка — квадрат с фоном `--ids__surface`, внутри сверху вниз:

1. **Фото** в левом верхнем углу. Форма — `card.photoShape`:
   `circle` (кружок), `square` (квадрат), `landscape` (горизонтальный 4:3),
   `portrait` (вертикальный 3:4). Обёртка режет фото снизу: лицо должно быть
   в верхней части кадра.
2. **Имя** всегда в две строки (имя / фамилия, делится по первому пробелу в
   загрузчике), выключка влево.
3. **Графика** в правом нижнем углу, ограничена по высоте, не по ширине.
   При квадратном фото иконка стоит под именем, слева; канвас всегда в углу.
   Логотип `pndlnk` —
   исключение: абсолютом в правом верхнем углу на 60% ширины, поверх фото.
   Канвасы на плитке свой фон не рисуют (`data-transparent`).

Плитка — пропорции 3:4, без рамок, между плитками малый гэп сетки. Канвасы на плитке без заливок (`data-background-color="transparent"`),
сквозь фигуры видна плитка; у `pndlnk` внутренний цвет букв берёт фон плитки
(`"background"`), читается каждый кадр и меняется вместе с ховером.

Без фото на месте фото — прямоугольник 4:3 одного из фирменных цветов
(`card.fallbackColor`): `pndlnk-dark-gray`, `pndlnk-red`, `pndlnk-red-tinted`,
`pndlnk-gold`, `pndlnk-gold-tinted`. Чёрный, белый и светло-серый не
используются: сливаются с текстом или с плашкой.

Усложнения (нахлёсты, исключения) появятся позже поверх этой базы.

## Параметры в `people.json`

```json
"card": {
  "photoShape": "circle",
  "photoWidth": 60,
  "photoBleed": true,
  "tone": "dark",
  "fallbackColor": "pndlnk-gold-tinted",
  "graphic": { "kind": "canvas", "type": "layered-house" },
  "note": "почему так — для следующего, кто будет размечать"
}
```

- `photoWidth` — ширина фото в процентах плитки; без него — дефолт формы
  (кружок и квадрат 33%, горизонтальный 60%, вертикальный 35%).
- `photoBleed` — фото без полей, вплотную к левому и верхнему краю.
- `tone` — `dark` для тёмной плитки (класс `.dark`, токены переключаются).

- `graphic.kind` — `canvas` (анимация: `sphere`, `layered-house`, `pndlnk`,
  `splash`) или `icon` (статичная иконка продукта: `etalon`, `base`, `evp-dev`,
  `evp-checkup`, `goals`, `ksc`, `checkup`, `cxsl`, `dkcp-cert`); `null` — без графики.
- Выпускник CX:SL без своей графики автоматически получает иконку `cxsl`.
- Неизвестные значения загрузчик заменяет дефолтом (`circle`,
  `pndlnk-gold-tinted`, без графики) и пишет предупреждение `[people]` в лог сборки.
- `card.explicit` в загруженных данных — `false`, если форму никто не назначал:
  так видно, кого ещё не размечали.

## Входы для выбора

| Что смотреть | Как узнать |
|---|---|
| Есть ли фото | `photo` в записи |
| Пропорции и где лицо | `sips -g pixelWidth -g pixelHeight <файл>`; открыть файл и посмотреть, в какой трети кадра лицо |
| Качество фото | мелкое (< 500 px по короткой стороне), шумное, пёстрый фон — считать слабым |
| Готовая обрезка | фото уже вырезано в круг или с цветной подложкой — только `circle` |
| Вид графики | `canvas` занимает внимание и анимируется, `icon` — тихий бейдж |
| Статус | бюрошники и партнёры важнее студентов для выразительных форм |
| Соседи | порядок в `people.json` = порядок плиток в сетке (3 в ряд на десктопе, 2 на мобиле) |

## Эвристики (по приоритету)

1. **Дефолт — `circle`.** Если ничего не выделяет фото, кружок.
2. **Форма от кадра.** Вертикальное студийное фото хорошего качества →
   `portrait`. Горизонтальный кадр → `landscape`. Плотно кадрированный портрет
   на нейтральном фоне → `square`. Слабое фото → `circle` (кружок прощает больше).
3. **Разнообразие.** Соседние плитки по возможности не повторяют форму фото и
   цвет блока, если есть законная альтернатива по пункту 2.
4. **Бюджет анимации.** Не больше четырёх канвасов на странице; лишние заменять
   иконкой или убирать графику.
5. **Без фото.** Цвета чередовать по списку выше; два соседних блока без фото —
   разных цветов.
6. **Нахлёст** допустим только у `pndlnk` поверх фото; остальная графика не
   пересекается с фото.
7. **Тёмная плитка** — для ч/б фото или фото на цветной подложке, и чтобы
   ряд не был однотонным; не больше трети плиток тёмные.

## Куда писать и как проверять

Значения — в `card.*` записи человека, обоснование — в `card.note`.
Проверка без сборки:

```bash
node -e "const p=require('./src/data/loadProjects.js')();const r=require('./src/data/loadPeople.js')(p);console.log(r.people.map(x=>[x.slug,x.card.photoShape,x.card.fallbackColor,x.card.graphic&&x.card.graphic.kind+':'+x.card.graphic.type,x.card.explicit]))"
```

Предупреждения `[people]` в выводе — значит, в данных опечатка. После правки
`people.json` dev-сервер нужно перезапустить: данные читаются при старте.
