# Плитки людей на /people: как выбирать компоновку

Документ для агента (или человека), который размечает плитки в
[`src/data/people.json`](../src/data/people.json). Вёрстка —
[`src/styles/widgets/people-cards.css`](../src/styles/widgets/people-cards.css),
разметка — [`src/includes/macros/people-card.njk`](../src/includes/macros/people-card.njk).

## Базовая компоновка

Плитка — прямоугольник 2:3 с фоном светлее `--ids__surface` (на ховере — на полпути к сёрфейсу), внутри сверху вниз:

1. **Фото** в левом верхнем углу. Два вида, форма — `card.photoShape`:
   - мелкое в углу: `circle` (кружок) или `square` (квадрат), 25% ширины
     плитки, с полем от края; фото режется по квадрату сверху — лицо должно
     быть в верхней части кадра;
   - крупное на всю ширину: `wide` — квадрат без полей на всю ширину плитки
     (верхние две трети), кадр заполняет квадрат и центрируется
     (`object-fit: cover`): лицо должно быть в середине кадра по горизонтали.
     Подложка `card.photoBackdrop` (hex `#rrggbb`, цвет фона съёмки у края
     кадра) видна только пока фото грузится; подбирает агент один раз при
     вёрстке, не алгоритм.
2. **Имя** в одну строку, выключка влево. Под именем одной строкой — текущие статусы без периодов
   (`cardStatuses`; выпускники получают статус `graduate` в `statuses`,
   отдельной логики нет) и до трёх самых частых ролей из проектов
   (`cardRoles`: роли режутся по запятой на атомарные, в нижнем регистре).
3. **Графика** в правом нижнем углу, ограничена по высоте, не по ширине.
   При квадратном фото иконка стоит под именем, слева; канвас всегда в углу.
   Логотип `pndlnk` —
   исключение: абсолютом справа на 60% ширины, поверх фото, со своим меньшим
   отступом справа. Положение по вертикали — `graphic.align`: `top`
   (по умолчанию, вверху с малым отступом), `middle` (по центру плитки),
   `photo-bottom` (нижний край логотипа по нижнему краю крупного фото).
   Канвасы на плитке свой фон не рисуют (`data-transparent`).

Плитки — пять в ряд (три на мобиле), без рамок, между плитками минимальный
гэп (`--ids__gap-xs`); гэп — паддинг ссылки, зоны ховера соседей смыкаются. Канвасы на плитке свой фон не рисуют, заливки фигур берут фон плитки
(`"background"`): цвет читается каждый кадр и меняется вместе с ховером.

Без фото на месте фото — квадрат на всю ширину (как крупное фото) одного из фирменных цветов
(`card.fallbackColor`): `pndlnk-dark-gray`, `pndlnk-red`, `pndlnk-red-tinted`,
`pndlnk-gold`, `pndlnk-gold-tinted`. Чёрный, белый и светло-серый не
используются: сливаются с текстом или с плашкой.

Усложнения (нахлёсты, исключения) появятся позже поверх этой базы.

## Параметры в `people.json`

```json
"card": {
  "photoShape": "wide",
  "photoBackdrop": "#c3c6cb",
  "tone": "dark",
  "fallbackColor": "pndlnk-gold-tinted",
  "graphic": { "kind": "canvas", "type": "pndlnk", "align": "photo-bottom" },
  "note": "почему так — для следующего, кто будет размечать"
}
```

- `photoShape` — `circle` | `square` | `wide`; размеры задаёт вёрстка.
- `photoBackdrop` — только для `wide`: hex-цвет подложки справа от фото.
  Без него загрузчик предупреждает, подложкой будет фон плитки. Это
  единственный литерал цвета в данных: он берётся из фотографии, не из токенов.
- `tone` — `dark` для тёмной плитки (класс `.dark`, токены переключаются).

- `graphic.kind` — `canvas` (анимация: `sphere`, `layered-house`, `pndlnk`,
  `splash`) или `icon` (статичная иконка продукта: `etalon`, `base`, `evp-dev`,
  `evp-checkup`, `goals`, `ksc`, `checkup`, `cxsl`, `dkcp-cert`); `null` — без графики.
- `graphic.align` — только для `pndlnk`: `top` | `middle` | `photo-bottom`.
- Выпускник CX:SL без своей графики автоматически получает иконку `cxsl`.
- Неизвестные значения загрузчик заменяет дефолтом (`circle`,
  `pndlnk-gold-tinted`, без графики) и пишет предупреждение `[people]` в лог сборки.
- `card.explicit` в загруженных данных — `false`, если форму никто не назначал:
  так видно, кого ещё не размечали.

### Поправочные коэффициенты графики

Фигуры разного оптического веса, поэтому у части типов размер скорректирован
в `people-cards.css` относительно базового (канвас 60% ширины плитки, иконка
2.8rem высоты); коэффициенты подобраны глазом:

| Графика | Коэффициент |
|---|---|
| `splash` | 133% ширины, сдвиг вправо-вниз на 10% своего размера |
| `base` (иконка Базы ДКЦП) | 90% высоты |

## Входы для выбора

| Что смотреть | Как узнать |
|---|---|
| Есть ли фото | `photo` в записи |
| Пропорции и где лицо | `sips -g pixelWidth -g pixelHeight <файл>`; открыть файл и посмотреть, в какой трети кадра лицо |
| Качество фото | мелкое (< 500 px по короткой стороне), шумное, пёстрый фон — считать слабым |
| Готовая обрезка | фото уже вырезано в круг или с цветной подложкой — только `circle` |
| Вид графики | `canvas` занимает внимание и анимируется, `icon` — тихий бейдж |
| Статус | бюрошники и партнёры важнее студентов для выразительных форм |
| Соседи | порядок в `people.json` = порядок плиток в сетке (5 в ряд на десктопе, 3 на мобиле) |

## Эвристики (по приоритету)

1. **Дефолт — `circle`.** Если ничего не выделяет фото, кружок.
2. **Форма от кадра.** Студийное фото хорошего качества на ровном фоне
   (любых пропорций) → `wide` с подложкой цвета фона съёмки. Плотно
   кадрированный портрет на нейтральном фоне → `square`. Слабое фото или
   пёстрый фон, из которого не взять цвет подложки → `circle` (кружок прощает
   больше). Крупных фото — не больше трети плиток.
3. **Разнообразие.** Соседние плитки по возможности не повторяют форму фото и
   цвет блока, если есть законная альтернатива по пункту 2.
4. **Бюджет анимации.** Не больше четырёх канвасов на странице; лишние заменять
   иконкой или убирать графику.
5. **Без фото.** Цвета чередовать по списку выше; два соседних блока без фото —
   разных цветов.
6. **Нахлёст** допустим только у `pndlnk` поверх фото; остальная графика не
   пересекается с фото.
7. **Тёмная плитка** — для ч/б фото или фото на цветной подложке, и чтобы
   ряд не был однотонным; не больше трети плиток тёмные.

## Куда писать и как проверять

Значения — в `card.*` записи человека, обоснование — в `card.note`.
Проверка без сборки:

```bash
node -e "const p=require('./src/data/loadProjects.js')();const r=require('./src/data/loadPeople.js')(p);console.log(r.people.map(x=>[x.slug,x.card.photoShape,x.card.photoBackdrop,x.card.fallbackColor,x.card.graphic&&x.card.graphic.kind+':'+x.card.graphic.type,x.card.explicit]))"
```

Предупреждения `[people]` в выводе — значит, в данных опечатка. После правки
`people.json` dev-сервер нужно перезапустить: данные читаются при старте.
