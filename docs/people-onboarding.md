# Люди: норма плитки и заведение нового человека

Документ для агента в Claude Code (и для человека), который заводит нового
человека в разделе «Люди»: опрашивает редактора, обрабатывает фото, заполняет
данные и роли, делает страницу, проверяет сборку. Схема данных —
[`people-data.md`](people-data.md); вёрстка —
[`src/styles/widgets/people-cards.css`](../src/styles/widgets/people-cards.css),
разметка — [`src/includes/macros/people-card.njk`](../src/includes/macros/people-card.njk).

## 1. Кто и с кем

Агент разговаривает только с **редактором сайта** (обычно Даша, иногда Миша или
Женя). Сам человек, чью карточку делаем, в разговоре не участвует и ему ничего
не пишется. Всё, чего агент не знает, он спрашивает редактора; ничего не
додумывает: статус, годы, согласие, текст. Считается, что редактор уже узнал у
Миши то, что знает только Миша (статусы, годы, текст о человеке).

## 2. Норма: что уже свёрстано и не меняется под человека

Сетка `/people/`: пять плиток в ряд (три на мобиле), плашка 3:4, гэп
`--ids__gap-xs` паддингом ссылки (ховер соседей смыкается без зазора), фон
плашки — сёрфейс на 40%, на ховере на 70%. Плитка сверху вниз:

1. **Фото** в левом верхнем углу, два вида (`card.photoShape`):
   - `circle` — мелкое, кружок 25% ширины плитки, с полем от края; фото режется
     по квадрату сверху, лицо должно быть в верхней части кадра;
   - `wide` — крупное на всю ширину без полей, пропорции 7:6, кадр заполняет
     обёртку и центрируется (cover). Подложка `card.photoBackdrop` (hex цвета
     фона съёмки у края кадра) видна, пока фото грузится.
   Без фото — блок 7:6 на всю ширину фирменного цвета `card.fallbackColor`:
   `pndlnk-dark-gray`, `pndlnk-red`, `pndlnk-red-tinted`, `pndlnk-gold`,
   `pndlnk-gold-tinted` (чёрный, белый и светло-серый не используются: сливаются
   с текстом или плашкой).
2. **Имя** в одну строку, моно, жирное, с подчёркиванием.
3. **Строка статуса**: текущие статусы без периодов (`cardStatuses`) и до трёх
   самых частых ролей из проектов (`cardRoles`; роли режутся по запятой на
   атомарные, в нижнем регистре). Выпускники получают статус `graduate` в
   `statuses`, отдельной логики нет.
4. **Графика** (`card.graphic`), по умолчанию нет:
   - иконка продукта (`kind: "icon"`) — под строкой статуса, слева, высота
     2.4rem; типы `etalon`, `base`, `evp-dev`, `evp-checkup`, `goals`, `ksc`,
     `checkup`, `cxsl`, `dkcp-cert`;
   - анимация (`kind: "canvas"`) — крупно, 42% ширины плитки, в правом нижнем
     углу; типы `sphere`, `layered-house`, `pndlnk`, `splash`. Свой фон канвас
     не рисует, заливки берут фон плитки и следуют за ховером.
   - Выпускник CX:SL без своей графики получает иконку `cxsl` автоматически.

Тёмная плитка — `card.tone: "dark"` (класс `.dark`, токены переключаются).

### Поправочные коэффициенты графики

Фигуры разного оптического веса, поэтому у части типов размер скорректирован
в `people-cards.css` относительно базы (иконка 2.4rem высоты, канвас 42%
ширины); коэффициенты подобраны глазом. Новый тип графики без коэффициента
ставится по базе; если выглядит не по размеру — коэффициент добавляет Женя.

| Графика | Коэффициент |
|---|---|
| `base` (иконка Базы ДКЦП) | 90% высоты: плашка тяжелее остальных |
| `cxsl` (иконка CX:SL) | сдвиг влево-вверх на 8% — компенсация поля внутри SVG |
| `splash` | 133% ширины канваса; сдвиг под угол при возврате подбирать заново |

### Внутренняя страница

Портрет в шапке следует форме фото на плитке: `wide` → большой квадрат
(17.6rem), `circle` → кружок (5.6rem); оба квадратные, кадр по центру. На мобиле
оба кружком 20% ширины. Без фото шапка без портрета. Ниже — таблица «Проекты и
продукты» из ролей и список обучения; текст о человеке — в HTML страницы.

## 3. Опросник редактора

Вопросы по порядку. Ответы редактора — единственный источник; если ответа нет,
поле остаётся пустым/`null`, а вопрос записывается в `card.note` («уточнить у
Миши: …»).

| # | Вопрос | Куда идёт ответ |
|---|---|---|
| 1 | Имя и фамилия, как писать на сайте | `name`; `slug` — транслит `имя-фамилия` латиницей (`evgeny-khomich`); проверить, что такого slug нет в `people.json` и файла нет в `src/people/` |
| 2 | Есть ли согласие человека на публичный профиль | `public_profile`; без согласия запись всё равно заводится, но страница не собирается и в список не попадает |
| 3 | Статус (бюрошник / срединник / партнёр / выпускник) и с какого года; были ли прошлые статусы и в какие годы | `statuses[]` — `{ "status": "buro" \| "mid" \| "partner" \| "graduate", "from": год или null, "to": год или null }`; у каждого статуса свой период |
| 4 | Учился ли в CX:SL или КСЦ: поток, год, номер сертификата | `education[]` (`{ "kind": "cxsl" \| "ksc", "flow"?, "year"? }`), `certificate` (`false` или `{ "number" }`); выпускник CX:SL дополнительно получает статус `graduate` в `statuses` |
| 5 | Есть ли фото: путь к файлу | шаг «Фото»; «нет» → цветной блок |
| 6 | Нужна ли графика на плитке (по умолчанию — нет). Если да: иконка или анимация, какая | `card.graphic`; список типов в разделе 2 |
| 7 | Есть ли текст о человеке от Миши (абзацы) | страница `src/people/<slug>.html`; «пока нет» → страница без текста |
| 8 | Только если человека нет в таблице Богдана или там «Уточнить»: в каких проектах с сайта участвовал и в какой роли | `project-roles.json` |

## 4. Шаги

### Фото

1. Размер и формат: `sips -g pixelWidth -g pixelHeight <файл>`. Короткая сторона
   меньше 500 px — слабое фото.
2. Открыть файл (Read показывает картинку) и описать редактору: фон (ровный
   студийный / пёстрый), где лицо в кадре, ч/б или цвет, качество, есть ли уже
   готовая обрезка (круг, цветная подложка).
3. Предложить форму и дождаться подтверждения:
   - студийное фото хорошего качества на ровном фоне, лицо в середине кадра →
     `photoShape: "wide"`; крупных плиток на странице — не больше трети;
   - остальное (слабое, пёстрый фон, уже вырезанное в круг) → `"circle"`;
     кружок прощает больше.
4. Конвертация в `src/assets/people/<slug>.jpg`:

   ```bash
   sips -s format jpeg -s formatOptions 82 --resampleWidth 1200 <исходник> --out src/assets/people/<slug>.jpg
   ```

   Исходник меньше 1200 px по ширине вверх не ресемплить (`--resampleWidth`
   убрать). PNG с прозрачностью или уже вырезанный круг на подложке — оставить
   PNG как есть, имя по slug. Кадр не резать: cover центрирует сам.
5. Для `wide` подобрать `photoBackdrop` — hex цвета фона съёмки у правого
   края кадра (глазом, один раз).

### Тон и цвет блока

- Посмотреть соседей в группе статуса (порядок `people.json`). Тёмных плиток —
  не больше трети на странице и не две подряд. Кандидаты на `tone: "dark"` —
  ч/б фото и фото на цветной подложке.
- Без фото — `fallbackColor` из списка в разделе 2; два соседних блока без
  фото — разных цветов.

### Запись в `people.json`

Схема — [`people-data.md`](people-data.md). Порядок записей = порядок плиток:
список сгруппирован по статусу (бюрошники → срединники → партнёры →
выпускники), новый человек встаёт **последним в своей группе** (после последнего
с тем же текущим статусом). Других людей не переставлять. В `card.note`
записать обоснование решений: форма фото и почему, тон, графика, что осталось
уточнить.

```json
{
  "slug": "imya-familiya",
  "name": "Имя Фамилия",
  "statuses": [{ "status": "mid", "from": 2026, "to": null }],
  "education": [],
  "certificate": false,
  "public_profile": true,
  "photo": "/assets/people/imya-familiya.jpg",
  "card": {
    "photoShape": "circle",
    "graphic": null,
    "note": "Кружок: фото на пёстром фоне; статус от Миши через Дашу, год уточнить"
  }
}
```

Необязательные поля `card`: `tone: "dark"`, `photoBackdrop` (только с `wide`),
`fallbackColor` (только без фото), `graphic: { "kind", "type" }`.

### Роли в проектах

1. Прочитать таблицу Богдана «люди × проекты» — Google Sheet
   `1cwxZAOuXjF-XW02otETyLPzVCdhIaQ4_ao05I2zKOhs` (коннектор Google Sheets:
   `get_spreadsheet`, затем `get_values` листа целиком). Строки — проекты,
   колонки — люди.
2. Найти колонку человека; взять все ячейки, кроме пустых и «Уточнить».
   Ячейки «Уточнить» и отсутствие человека в таблице — вопрос 8 редактору.
3. Сопоставить строки со слагами проектов по приложению ниже; проекты, которых
   нет на сайте, не брать.
4. Добавить в `src/data/project-roles.json` записи
   `{ "project": "<slug проекта>", "person": "<slug человека>", "role": "<как в таблице>" }`.
   Роль — текст как в таблице (загрузчик сам режет по запятой для плитки).

### Страница `src/people/<slug>.html`

Без текста — как [`src/people/bogdan-burdin.html`](../src/people/bogdan-burdin.html):

```njk
{% extends 'layout.html' %}
{% from 'macros/person-page-meta.njk' import personMeta, personProjects with context %}
{% set pageTitle = 'Имя Фамилия — Понедельник' %}
{% block content %}
<div class="ids__wrapper person-page">
  {{ personMeta(page) }}
  {{ personProjects(page) }}
</div>
<div class="ids__space XL"></div>
{% endblock %}
```

С текстом — как [`src/people/dasha-kochenova.html`](../src/people/dasha-kochenova.html):
`{% call personMeta(page) %}<p>…</p><p>…</p>{% endcall %}`, абзацы как прислал
Миша, смысл и слова не править; типографика как на существующих страницах
(неразрывный пробел после однобуквенных предлогов, `&shy;` в длинных словах
при необходимости).

### Проверка

1. Данные без сборки — предупреждений `[people]` быть не должно:

   ```bash
   node -e "const p=require('./src/data/loadProjects.js')();const r=require('./src/data/loadPeople.js')(p);const x=r.people.find(x=>x.slug==='<slug>');console.log(JSON.stringify({card:x.card,portrait:x.portrait,statuses:x.cardStatuses,roles:x.cardRoles,projects:x.projects.length},null,2))"
   ```

2. Dev-сервер перезапустить: данные людей читаются при старте
   (`npm run dev -- --port=8083`; 8080 занят другим проектом).
3. Открыть `/people/` и `/people/<slug>/`, сказать редактору, что смотреть:
   плитка в своей группе, форма фото, строка статуса и ролей, таблица проектов.
4. Коммитить только по просьбе редактора.

## 5. Чего агент не делает

- Не сочиняет текст о человеке, статусы и годы; не предполагает согласие.
- Не ставит графику без просьбы редактора.
- Не меняет CSS, макросы и загрузчик ради одного человека. Новый тип графики,
  новое правило размещения или коэффициент — задача для Жени, с записью в этот
  документ.
- Не переставляет других людей и не правит их записи.
