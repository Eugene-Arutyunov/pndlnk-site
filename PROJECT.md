# Документация проекта

## Структура

Проект построен на Eleventy (11ty) версии 3.0.0.

- `src/` — исходные файлы
- `_site/` — сгенерированные файлы (не коммитится)
- `eleventy.config.js` — конфигурация Eleventy

## Дизайн-система

Проект использует IDS (Intuition Design System). Ядро завендорено в `src/ids/`
и эволюционирует вместе с сайтом — эталонная ids (https://intuition-tech.github.io/ids)
служит источником конвенций, но не подключается как зависимость.

Живая витрина системы — страница `/style` (`src/style.html`): токены рендерятся
из живого CSS и не могут разойтись с кодом. Полный реестр блоков — `REGISTRY.md`.

### Слои

Порядок подключения в `src/css-bundle.njk` = каскад:
**токены → ресет → настройки → композиция страницы → ядро → компоненты → инклуды → виджеты → страницы**.

- **Токены** (`src/ids/tokens/`) — жёсткий контракт: использовать как есть, не
  переименовывать, не заводить алиасы, не обобщать.
  - `palette.css` — сырые `rgb()`-значения, единственный источник правды для цвета.
    Сырые цвета нигде больше не появляются.
  - `colors.css` — семантические роли (`--ids__text`, `--ids__hover`, …) и брендовые
    (`--ids__pndlnk-*`); каждая ссылается на палитру. Тёмные блоки — класс `.dark`
    на секции, переключение только в этом файле.
  - `scales.css` — именованные шкалы: спейсеры, гэпы, радиусы, толщины границ,
    длительности и изинги. Магические значения в новом коде не заводить —
    брать шаг шкалы.
- **Компоненты** (`src/styles/components/`) — референсные образцы UI-элементов,
  файл на компонент. Компонент не содержит сырых значений — только токены.
- **Виджеты** (`src/styles/widgets/`) — крупные куски функциональности,
  собранные из компонентов и токенов.
- **Страницы** (`src/styles/*.css`, `src/styles/cases/`) — то, что не обобщается.

### Правила работы с цветом

- В вёрстке — только семантические токены. Палитра напрямую — лишь там, где цвет
  не должен зависеть от темы (пример: `.pndlnk-promo-link.inverted`), с
  комментарием-обоснованием.
- Прозрачность выводится на месте применения:
  `color-mix(in srgb, var(--ids__text) 55%, transparent)` — отдельные токены
  для вариантов прозрачности не заводятся.
- Стандартная рамка — `--ids__border`.

### Брейкпоинт

Единственный брейкпоинт — 768px, форма записи `@media (width < 768px)`.

## Компоненты

## Шрифты

В проекте используются кастомные шрифты:

- **CoFoGothic** (`--gothic`) — основной шрифт текста и заголовков
- **CoFoSansSemi-Mono** (`--mono`) — акцентные заголовки, навигация, подписи
- **Newton** (`--serif`) — глоссарий и справочные вставки
- **CoFoHand** (`--hand`) — имитация рукописного текста
- **Robert** — не используется (блок в settings.css закомментирован)

### Оптимизация загрузки

Шрифты подключаются двумя способами для ускорения загрузки:

1. **Предзагрузка в HTML** (в `src/includes/layout.html`):

```html
<link
  rel="preload"
  href="/fonts/CoFoGothic-VF-Trial.ttf"
  as="font"
  type="font/ttf"
  crossorigin />
<link
  rel="preload"
  href="/fonts/CoFoSansSemi-Mono-VF-Trial.ttf"
  as="font"
  type="font/ttf"
  crossorigin />
```

2. **Объявление в CSS** (в `src/ids/settings.css`):

```css
@font-face {
  font-family: "CoFoGothic";
  font-style: normal;
  font-display: swap;
  src: url("fonts/CoFoGothic-VF-Trial.ttf") format("truetype");
}
```

Предзагрузка в HTML позволяет браузеру начать загрузку шрифтов параллельно с CSS, что устраняет мигание системного шрифта при переходах между страницами.

## Стили и CSS

### Единицы измерения

В проекте используется строгое правило для единиц измерения в CSS:

- **em** — инлайновые элементы и их отступы, типографика и всё, что должно
  масштабироваться вместе с кеглем окружения: размеры шрифта, отступы вокруг
  текста, трансформации, размытие
- **rem** — блочная геометрия, которая не должна плавать при смене локального
  кегля: паддинги ячеек таблиц и строк-разделителей, структурные отступы
  блоков, в которых соседствуют разные размеры шрифта
- **px** — только для бордеров и подчеркиваний (`border`, `outline`, `text-decoration-thickness`)

Это обеспечивает масштабируемость интерфейса и корректную работу на разных устройствах.

```css
/* Правильно */
font-size: 1.2em;
margin: 2em 1em; /* отступы текстового блока — em */
padding: 0.4rem 0.5rem; /* паддинг ячейки таблицы — rem */
transform: translateZ(5em);
filter: blur(0.12em);
border: 1px solid red;

/* Неправильно */
font-size: 16px;
margin: 32px 16px;
filter: blur(2px);
padding: 0.5em 0; /* в ячейке таблицы: высота строки зависела бы от кегля ячейки */
```

Тест на выбор единицы: если у соседних элементов разный `font-size`, а отступы
должны быть одинаковыми — это rem; если отступ должен расти вместе с текстом —
это em. Магические множители в `calc()` — те же магические числа: шаг размера
берётся со шкалы токенов, а не выводится умножением.

### Переходы (transitions)

Никогда не используем `transition: all`. Всегда указываем только те свойства, которые действительно нужно анимировать.

```css
/* Правильно */
transition: background-color 0.5s ease;
transition:
  opacity 0.5s ease,
  transform 0.5s ease;

/* Неправильно */
transition: all 0.2s ease;
```

**Причины:**

- `transition: all` замедляет производительность, анимируя все изменяющиеся свойства
- Может вызывать неожиданные анимации при изменении CSS
- Менее предсказуемое поведение при рефакторинге стилей

#### Ховер-анимации

При ховере все изменения происходят мгновенно (время перехода 0 секунд), а при потере ховера используется анимация со стандартным временем 0.5s.

```css
.element {
  background-color: var(--ids__accent);
  transition: background-color var(--ids__duration-slow) var(--ids__easing-base);

  &:hover {
    background-color: var(--ids__hover);
    transition-duration: var(--ids__duration-instant);
  }
}
```

**Логика:** Пользователь должен мгновенно видеть реакцию на свои действия, но плавный возврат в исходное состояние создает приятное ощущение.

### Изображения

Никогда не стилизуем тег `<img>` напрямую. Изображение всегда занимает доступное место, а его габариты определяет только контейнер.

```css
/* Правильно */
.author-photo {
  width: 10em;
  height: 10em;
}

.author-photo img {
  /* img наследует размеры от контейнера */
}

/* Неправильно */
img {
  width: 10em;
  height: 10em;
  border-radius: 50%;
}
```

Если нужно скругление, трансформации или другие эффекты — создаем отдельную обёртку:

```css
.image-wrapper {
  width: 10em;
  height: 10em;
  border-radius: 50%;
  overflow: hidden;
}

.image-wrapper img {
  /* img заполняет обёртку */
}
```
